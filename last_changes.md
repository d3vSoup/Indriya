### Feature A: "Ask the Web" Button in `deaf.html` (Powered by Tavily)
**Effort: 3–4 hours | Impact: Very High**

**The Problem:** The teacher says "photosynthesis" — but a deaf student has never heard of it. The class has moved on. The student is stuck with no way to quickly look it up without leaving the room.

**The Feature:**
- When the deaf student clicks any **ISL gloss word card** (e.g., the card that says `PHOTOSYNTHESIS`), a small "🔎 Look up" button appears next to it.
- Clicking it fires a `POST /api/tavily-search` request with the word as the query.
- The backend calls the **Tavily Search API** and returns the top 3 web results (title + 1-sentence snippet + URL).
- A small **info panel slides out** showing these 3 results — the student can click through to learn more.

**Why it wins:** A deaf student can self-serve contextual definitions from the live web, right inside the classroom tool, without ever leaving the page. This is the "Silent Handshake" philosophy applied to knowledge.

**What NOT to touch:**
- Do not modify the existing WebSocket broadcast logic.
- Do not change how ISL gloss cards are rendered (just add the click handler on top).
- The existing `/api/simplify` endpoint is unchanged.

**Backend change needed (in `backend/main.py`):**
```python
# Add a NEW endpoint — do not modify any existing ones
@app.post("/api/tavily-search")
async def tavily_search(request: dict):
    query = request.get("query", "").strip()
    if not query:
        return {"results": []}
    
    import httpx
    TAVILY_API_KEY = os.getenv("TAVILY_API_KEY")  # Add this key to .env and Render
    async with httpx.AsyncClient() as client:
        res = await client.post(
            "https://api.tavily.com/search",
            json={"query": query, "max_results": 3, "search_depth": "basic"},
            headers={"Authorization": f"Bearer {TAVILY_API_KEY}"},
            timeout=8.0
        )
    data = res.json()
    return {"results": data.get("results", [])}
```

**Frontend change needed (in `frontend/deaf.html`):**
- Add a click listener on ISL gloss word `<span>` elements.
- On click, call `BACKEND_HTTP + '/api/tavily-search'` with the word as query.
- Show a small side panel with the 3 results: title, snippet, and a clickable URL.
- This panel should be a new `<div id="tavilyPanel">` injected into the page — do not modify the existing modals.

**Environment variable to add:**
```
TAVILY_API_KEY=tvly-xxxxxxxxxxxxxxxxxxxx
```
Get your free API key at https://app.tavily.com

### Feature B: n8n Lesson Notification Workflow
**Effort: 2–3 hours | Impact: High (no code needed in the app itself)**

**The Problem:** Parents and support teachers of deaf/blind students have no idea what was covered in class. They find out at the end of the week, which is too late to reinforce learning at home.

**The Feature:**
- Set up a free self-hosted or cloud n8n workflow that runs whenever the teacher ends a session.
- The workflow is triggered by a simple HTTP call from the frontend (a "📬 Send Summary to Parents" button next to Export PDF in `deaf.html`).
- The n8n workflow then:
  1. Receives the lesson summary text (already generated by `/api/summarise`).
  2. Formats it into a parent-friendly email (e.g., "Today's class covered: 1. Photosynthesis ... 2. Water cycle ...").
  3. Sends the email via the n8n Email node (using Gmail or SMTP).

**Why it wins:** n8n is the official "AI Workflow Automation Platform". Using it here demonstrates exactly what it's built for — orchestrating multi-step workflows triggered by real events. It's zero-code on the n8n side and minimal code on the frontend.

**What NOT to touch:**
- Do not change the existing `/api/summarise` endpoint.
- The existing PDF export button is unchanged — this is an *additional* button.

**Minimal Frontend change needed (in `frontend/deaf.html`):**
```javascript
// Add a NEW button "📬 Notify Parents" next to Export PDF button
// On click, it calls the existing openSummariseModal() to get the summary,
// then sends it to the n8n webhook URL:

window.notifyParents = async function(summaryText) {
  const N8N_WEBHOOK = "https://your-n8n-instance/webhook/bharat-shakti-notify";
  await fetch(N8N_WEBHOOK, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      summary: summaryText,
      timestamp: new Date().toISOString()
    })
  });
  // Show a small "✅ Parents notified!" toast
};
```

**n8n Workflow to build (no code, just drag-and-drop nodes):**
1. **Webhook Trigger node** — receives `{ summary, timestamp }`.
2. **Set node** — formats the email body: "Indriya Lesson Summary — {{timestamp}}: {{summary}}".
3. **Send Email node** — sends to the parent email list.

**Get n8n:** Either sign up at https://n8n.io (cloud trial) or `npx n8n` to run locally.

### Feature C: Swytchcode API Guard for Groq (Production Hardening)
**Effort: 1–2 hours | Impact: Medium (makes existing features more reliable)**

**The Problem:** The existing Groq API calls in `main.py` have no retry logic, schema validation, or guardrails. If the Groq API changes a field name or returns a 429 (rate limit), the app fails silently.

**The Feature:**
- Install Swytchcode CLI: `npx swytchcode`
- Use it to wrap the Groq API calls in `main.py` with retry logic, idempotency keys, and structured error logging.
- This is purely a backend change — the frontend and all existing API endpoints remain completely identical.

**What NOT to touch:**
- All existing API route signatures (`/api/simplify`, `/api/summarise`, `/api/board-ocr`) remain unchanged.
- Response formats remain identical — frontend will not know the difference.

**Backend change needed:**
```bash
# In the backend directory
npx swytchcode init
npx swytchcode exec groq chat-completions --text "test" --model llama-3.3-70b-versatile
```

Then wrap the existing Groq calls:
```python
# BEFORE (in main.py):
chat_completion = groq_client.chat.completions.create(...)

# AFTER — add retry via Swytchcode:
import subprocess, json
result = subprocess.run(
    ["npx", "swytchcode", "exec", "groq", "chat-completions",
     "--model", "llama-3.3-70b-versatile", "--text", transcript],
    capture_output=True, text=True
)
data = json.loads(result.stdout)
```

Alternatively, use Swytchcode's Python SDK if available. Check https://docs.swytchcode.com.
